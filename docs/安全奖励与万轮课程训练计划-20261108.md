# PACER 安全奖励与 10000 Epoch 课程训练计划

> 日期：2026-11-08
>
> 状态：安全奖励已经实现；课程几何尚未达到开训条件。正式训练暂停，必须先完成直楼梯、有效宽度、起始距离采样和评测网格修复。
>
> 适用目标：在“平地—上楼—平台—下楼—平地”的混合场景中，同时改善落步位置、脚步防勾和膝盖/小腿避碰。
> 本计划补充 `课程训练计划-20261108-修订版.md`，并覆盖其中“Stage 1–2 关闭 safe stepping”的建议。

## 0. 核心决策

1. 从 PACER 官方初始 checkpoint（epoch 41,250）开始微调，不使用此前楼梯微调权重。
2. 正式微调预算为 **10000 epoch**，目标结束 epoch 为 51,250。
3. 总奖励固定为：

   \[
   r_{total}=0.6r_{task}+0.4r_{AMP}
   \]

4. 任务内部不把所有原始量作为独立大权重奖励，而是合并为：
   - 位置跟踪；
   - 能耗；
   - 速度跟踪；
   - 摆动安全复合模块；
   - 落脚质量复合模块；
   - 小幅实际撞击项。
5. 所有已验证的新奖励从 Stage 1 开始共同渐增；Stage 2–4 原则上保持同一奖励函数，只改变地形课程。
6. `edge penalty` 不进入默认 10000 epoch 主线。正向落脚质量先承担落点约束；edge 只作为独立消融候选。
7. 一次跨一阶或多阶都合法。安全奖励每个摆动周期只结算一次，不按跨越台阶数量累加。
8. 训练与评测使用同一终止规则；轻微小腿擦碰不再等同于真实摔倒。
9. 所有课程阶段都不生成连续斜面；训练地形只包含楼梯、平台和平地。
10. 在课程几何 P0 验收完成前，不启动 10000 epoch 正式训练。

### 0.1 几何术语（后文不得混用）

| 名称 | 符号 | 方向 | 含义 |
|---|---:|---|---|
| 踏高 / riser | `h` | 竖直 | 相邻踏面的高度差 |
| 踏深 / tread depth | `d` | 沿行进方向 | 单个踏面的前后进深 |
| 有效宽度 / stair clear width | `W` | 垂直行进方向 | 台阶面可供人物横向落脚和调整的总长度 |
| 起始距离 | `D_start` | 沿楼梯行进轴 | 初始根节点到第一块待跨越立板的有符号水平距离 |
| 平台长度 | `L_platform` | 沿行进方向 | 楼梯顶部或两段楼梯之间的平坦长度 |

本文所说“宽度课程”专指 `W`，不是踏深 `d`。训练日志和评测文件名必须同时记录 `h/d/W`。

### 0.2 2026-11-08 几何审计结论

以下结论覆盖此前关于 `stair_platform_size` 和训练覆盖率的判断：

1. 当前 `curriculum: true` 调用 `curiculum()`；其中 `pyramid_stairs_terrain(..., platform_size=3.0)` 被硬编码，配置中的 `stair_platform_size` 从未生效。
2. 因此此前“平台 3.0→1.0 使助跑距离 0.68→0.49 m”的因果结论撤回；差异视为采样波动，直到修复后重新做受控实验。
3. 当前训练生成器没有 `stair_width`，不能实现宽度课程；现有 pyramid 楼梯也不能提供方向明确的直楼梯走廊。
4. 当前出生点只用局部高度差筛选“附近有台阶”的点，不控制 `D_start`，也不结合人物朝向。64 env × 10 s 审计中，起始距离中位数为 1.11 m，只有 7.1% 落在 0.4–0.8 m；出现上台阶动作的环境由旧配置 21/64 降到 14/64。该配置不满足开训条件。
5. Stage 1 曾短暂包含 10% 斜面，相关结果作废。当前及以后所有 stage 的斜面概率必须为 0。
   配置名 `collision_slope_threshold` 仅表示立板风险检测中的局部高度梯度阈值，不代表生成斜面地形。
6. `wide_stairs.pkl` 上楼段实际宽度为 2.4 m，不是标称 2.8 m；`eval_r012_t028.pkl` 与 `eval_r018_t032.pkl` 的实际踏深均为 0.30 m。
7. 奖励、终止规则或评测网格任一改变后，旧评测只能作为历史记录；必须用冻结后的同一协议重新评测官方初始权重和新 checkpoint。

## 1. 现有实现与目标实现

### 1.1 改造前的代码奖励（历史基线）

改造前任务奖励为：

\[
r_{task}^{current}
=r_{location}+r_{power}
+\lambda_c r_{foot\_collision}
+\lambda_e r_{edge}
\]

改造前配置：

```yaml
enable_collision_penalty: true
enable_edge_penalty: false
collision_reward_weight: 0.20
edge_reward_weight: 0.10
```

改造前缺少：

- 显式速度跟踪；
- 正向脚部安全跨越；
- 膝盖/小腿净空；
- 膝部独立接触力惩罚；
- 正向落脚质量；
- 完整摆动周期的多立板扫掠。

上述缺项现已合并进有界安全模块；`edge penalty` 仍默认关闭，保留作消融开关。

### 1.2 目标奖励

\[
\boxed{
r_{task}
=r_{location}
+r_{power}
+0.10r_{velocity}
+r_{safety}
}
\]

其中：

\[
r_{safety}
=\operatorname{clip}
\left(
0.20r_{swing}
+0.15r_{landing}
+0.05r_{impact},
-0.25,
0.25
\right)
\]

最终进入 PPO 的奖励：

\[
\boxed{
r_{total}=0.6r_{task}+0.4r_{AMP}
}
\]

安全模块对最终奖励的最大直接影响被限制为：

\[
0.6\times[-0.25,0.25]=[-0.15,0.15]
\]

这样既提高任务项权重，又防止任务内部安全项过多而压倒 AMP 风格。

## 2. 奖励模块设计

### 2.1 位置跟踪

保持 PACER 现有形式：

\[
r_{location}
=\exp\left(-2\|p_{target}-p_{root}\|^2\right)
\]

职责：保证人物继续沿目标路线前进。

### 2.2 速度跟踪

\[
r_{velocity}
=\exp\left(
-k_v\|v_{root,xy}-v_{cmd,xy}\|^2
\right)
\]

若没有独立速度命令，则由相邻轨迹目标计算：

\[
v_{cmd}
=\frac{p_{target}(t+\Delta t)-p_{target}(t)}{\Delta t}
\]

建议初值：

```yaml
velocity_reward_weight: 0.10
velocity_error_scale: 2.0  # 首轮可在 2–4 内验证
```

职责：防止策略通过停在台阶前使速度相关碰撞风险归零。它是速度跟踪，不是“越快越好”。

### 2.3 摆动安全复合模块

摆动安全同时处理脚步防勾和膝盖/小腿避碰：

\[
\begin{aligned}
r_{swing}=\operatorname{clip}(&
0.60r_{foot\_clear}^{+}
+0.40r_{leg\_clear}^{+}\\
&+0.60r_{foot\_risk}^{-}
+0.40r_{leg\_risk}^{-},
-1,1)
\end{aligned}
\]

其中正向项只在摆动完成时结算，负向风险在摆动过程中密集计算，二者通常不会在同一时刻竞争。

#### A. 脚部密集风险

保留论文支持的速度—距离结构和当前实现的高度门：

\[
r_{foot\_risk}^{-}
=-g_{swing}I_{riser}
a_{effective}d_{weight}h_{gate}
\]

\[
a_{effective}
=\alpha+(1-\alpha)
\operatorname{clip}
\left(\frac{v_{approach}}{v_{ref}},0,1\right)
\]

\[
d_{weight}=\operatorname{clip}
\left(1-\frac{d}{d_{safe}},0,1\right)
\]

\[
h_{gate}=\sigma
\left(
\frac{h_{riser}+m-h_{foot}}{\sigma_h}
\right)
\]

建议：

```yaml
collision_speed_floor: 0.25  # alpha，建议验证范围 0.25–0.35
collision_unsafe_distance: 0.20
collision_height_margin: 0.04
collision_height_softness: 0.015
```

速度下限只对摆动腿生效，避免支撑脚静止在台阶附近时持续受罚。

#### B. 正向脚部安全跨越

对一次完整摆动期间跨越的所有立板集合 \(\mathcal E\) 计算最小净空：

\[
c_f=\min_{t,e,b}c(b,e,t),
\quad
b\in\{ankle,toe,sole\}
\]

\[
r_{foot\_clear}^{+}
=I_{touchdown}I_{|\mathcal E|>0}
S(c_f;0.02,0.06)
\]

达到约 6 cm 后奖励饱和，不鼓励无限高抬腿。

#### C. 膝盖/小腿密集风险

在膝—踝之间采样：

\[
q_s=(1-s)p_{knee}+sp_{ankle},
\quad s\in\{0,0.25,0.5,0.75\}
\]

为小腿使用约 0.04–0.054 m 的碰撞半径，并复用脚部的速度、距离和高度门结构：

\[
r_{leg\_risk}^{-}
=-\max_i(a_i d_i h_i)
\]

#### D. 正向膝腿安全跨越

\[
c_l=\min_{t,e,q}
\left[d(q,e)-r_{leg}\right]
\]

\[
r_{leg\_clear}^{+}
=I_{touchdown}I_{|\mathcal E|>0}
S(c_l;0.025,0.07)
\]

达到约 7 cm 后奖励饱和。

### 2.4 落脚质量复合模块

只在首次触地时结算：

\[
r_{landing}
=I_{touchdown}
\left(
0.55r_{support}
+0.30r_{margin}
+0.15r_{impact\_quality}
\right)
\]

其中：

\[
r_{support}=S(\rho;0.50,0.85)
\]

\[
r_{margin}=S(d_{edge};0.02,0.07)
\]

\[
r_{impact\_quality}
=\exp\left[-\left(
\frac{\max(0,-v_z^{touch})}{0.8}
\right)^2\right]
\]

说明：

- \(\rho\) 是脚底采样点受到踏面支撑的比例；
- \(d_{edge}\) 是有效脚底区域到最近台阶边缘的余量；
- 不指定必须落在下一阶；
- 跨一阶或多阶都只奖励一次；
- 稳定站在踏面上不会逐帧重复刷奖励。

### 2.5 实际撞击项

\[
r_{impact}
=-0.35C_{foot}-0.65C_{knee}
\]

每个身体分别计算接触力，不先对所有非足部身体求合力：

\[
C_i=
\operatorname{clip}
\left(
\frac{\|F_i\|-F_{free}}
{F_{sat}-F_{free}},0,1
\right)^2
\]

建议初值：

```yaml
contact_force_free: 20.0
contact_force_saturation: 150.0
```

该项只负责标记真实撞击，主要学习梯度仍来自摆动过程中的密集风险。

## 4. 奖励冲突控制

### 4.1 时间门控

| 状态 | 激活模块 |
|---|---|
| 平地正常行走 | location、velocity、power、AMP |
| 摆动腿接近立板 | swing risk |
| 脚和小腿已越过立板 | risk 由高度门关闭 |
| 完成摆动并首次触地 | foot/leg clear 与 landing |
| 真实脚/膝撞击 | impact |
| 稳定站在踏面上 | 不重复发 landing |

### 4.2 幅度控制

- 每个原始量先归一化到 `[0,1]` 或 `[-1,0]`；
- 摆动模块限制在 `[-1,1]`；
- 安全总和限制在 `[-0.25,0.25]`；
- 任务/AMP 固定为 `0.6/0.4`；
- 不按跨越台阶数量累加安全奖励。

### 4.3 不重复表达同一目标

- 默认使用正向 `landing margin`，`edge penalty` 保持关闭；
- 若未来启用 edge，应作为 landing 模块内部替代项，而不是再增加一个同级大权重；
- foot risk 不再额外复制一个相同定义的“脚尖高度奖励”；
- 膝碰撞实际接触只作为小幅 emergency signal，不与密集 leg risk 使用同等权重。

## 5. 终止规则

训练和评测统一使用：

1. 脚底正常接触：不终止；
2. 膝部接触力不超过 20 N：只记录，不触发连续碰撞计数；
3. 膝部接触力超过 20 N 且连续 3 个控制帧：终止；
4. 任一膝部单帧接触力超过 150 N：立即终止，不等待 3 帧；
5. 骨盆、Torso、Spine、Chest、Neck 或 Head 接触力超过 50 N：立即终止；
6. 胸—骨盆轴相对竖直方向倾斜超过 45°，或胸部相对地形高度低于 0.45 m：终止；
7. 偏离目标轨迹超过 `fail_dist`：保持现有终止；
8. 训练和评测不得使用不同终止规则。

旧的“任意非足部合力超过 50 N 即死亡”结果与新规则结果分开报告，不做直接能力对比。

注意：以上是当前代码的精确定义，不得简写成“150 N 连续 3 帧”。正式训练前必须分别统计每一种终止原因，避免把严格终止导致的短 episode 误判为策略没有学习能力。

## 6. 训练前验证（不计入 10000 epoch）

### 6.1 课程几何验证

先生成至少 100 个训练 tile，并从实际高度图/碰撞网格测量，而不是读取配置值：

```text
实测 riser       与采样目标误差 <= 0.005 m
实测 tread depth 与采样目标误差 <= 0.02 m
实测 clear width 与采样目标误差 <= 0.02 m
斜面 tile 数     0
方向不明确的 pyramid tile 数 0
D_start 位于目标区间的出生点 >= 80%
人物横向位置位于楼梯边缘内缩 0.20 m 后的比例 >= 95%
```

每个 rollout 记录 `terrain_id/h/d/W/D_start/ascent_or_descent`。配置分布与实际事件分布必须分别报告。

### 6.2 奖励静态/离线测试

必须覆盖：

- 平地站立、平地行走；
- 正常低速接近台阶；
- 低脚勾立板；
- 脚已经越过踏面；
- 膝/小腿接近立板；
- 安全跨一阶；
- 安全跨多阶；
- 上楼落脚；
- 下楼落脚；
- 脚底踩边；
- 膝部轻擦和高冲击。

验收：

- 所有分量为有限值；
- 平地不持续激活安全风险；
- foot/leg risk 在碰撞前 2–5 帧出现；
- 脚/腿越过立板后风险关闭；
- 上下楼落脚方向正确；
- 一次摆动只结算一次正奖励；
- 减速不能把危险几何风险完全清零。

### 6.3 冒烟训练

```text
num_envs: 128–256
epoch: 30–50
目标: 只验证运行、显存、NaN、保存和恢复
```

冒烟结果不得用于判断能力。

## 7. 10000 Epoch 课程

课程只使用直楼梯、平台与平地。楼梯生成器必须显式接收：

```yaml
stair_riser_min/max:
stair_tread_min/max:
stair_width_bins: []
stair_width_probs: []
stair_steps_min/max:
stair_platform_min/max:
stair_start_dist_min/max:
```

宽度采用离散分层抽样，保证每个宽度都有稳定样本量；不能只在连续区间内均匀抽样。`h/d/W` 原则上独立分层，困难 riser、窄 width、短 tread 的三重困难组合在 Stage 4 以前禁止出现。楼梯外侧必须是不可落脚区域或明显低于踏面的地面，使 `W` 真正影响碰撞和落脚，而不是只改变纹理或出生点。

### Stage 1：奖励适应与基本上下楼

```text
新增 epoch: 1500
累计新增: 1500
目标 checkpoint epoch: 42750
```

地形：

| 参数 | 范围 |
|---|---|
| riser | 0.08–0.12 m |
| tread | 0.35–0.42 m |
| width | 2.4–3.0 m |
| steps | 5–7 |
| platform | 1.5–2.0 m |
| start distance | 0.4–0.8 m |

宽度分层：

| `W` | 概率 |
|---:|---:|
| 3.0 m | 25% |
| 2.8 m | 45% |
| 2.4 m | 30% |

Stage 1 不出现小于 2.4 m 的楼梯，先让策略适应新奖励和准确落脚。

分布：

```text
60% 简单上楼
25% 简单下楼
15% 平地
```

奖励：

- task/AMP 从一开始固定为 `0.6/0.4`；
- 所有已验证新奖励乘同一个 warmup 系数；
- warmup 在前 16000 control steps（约 500 PPO epoch）从 0 线性升到 1；
- 奖励内部相对比例在 warmup 中保持不变；
- edge 始终关闭。

阶段门槛：

- 0.10 m 楼梯首阶通过率 ≥90%；
- 0.12 m 楼梯首阶通过率 ≥80%；
- 膝碰撞事件率 <5%；
- 危险落脚率 <5%；
- 楼梯前速度达到平地速度约 80% 以上；
- 无持续超过约 0.5 s 的台阶前停顿；
- 无明显夸张高抬腿。

## 8. 奖励在不同 Stage 的调整规则

### 8.1 默认规则

奖励阶段变化只有一次：Stage 1 前 500 epoch 的共同 warmup。

```text
Stage 1, epoch 0–500: 所有新任务奖励共同 0 → 100%
Stage 1, epoch 500–1500: 固定
Stage 2: 固定
Stage 3: 固定
Stage 4: 固定
```

课程阶段主要改变地形分布，不改变优化目标。

### 8.2 允许的受控调整

| 观察结果 | 单次只允许的优先调整 |
|---|---|
| 楼梯前速度下降超过 20% | `velocity` 0.10 → 0.15，或 speed floor 0.25 → 0.35，二选一 |
| 脚仍频繁勾立板 | 提高 swing 内 foot risk 比例，或扩大速度相关前视距离 |
| 膝盖仍频繁碰撞 | 提高 swing 内 leg risk 比例，最大建议 0.30 |
| 经常踩边 | landing 外部权重 0.15 → 0.20 |
| 过度高抬腿 | 降低净空满奖励阈值，不先改总权重 |
| 人物不敢落脚 | 检查 margin/edge 定义；不得通过提高速度权重强推 |
| AMP 风格明显恶化 | safety clip 0.25 → 0.20；task/AMP 仍保持 0.6/0.4 |
| 平地退化 | 增加平地样本比例，不先修改奖励 |

规则：

1. 每次只改一个因素；
2. 调整后至少观察 300–500 epoch；
3. 不因进入新 Stage 自动加大奖励；
4. 不同时调整 task/AMP、课程难度和多个安全权重；
5. 所有调整都必须记录 checkpoint、配置和对应评测指标。

## 9. 评测与 checkpoint

### 9.1 保存频率

- 每 250 epoch 保存 checkpoint；
- 不在正式训练中录制视频；
- 不默认把最后的 `Humanoid.pth` 当作最佳模型。

### 9.2 评测资产重建与冻结

旧 `wide_stairs.pkl`、`eval_r012_t028.pkl`、`eval_r018_t032.pkl` 不进入新协议。新生成器必须：

1. 根据 `W/2 + margin` 自动计算 y 网格范围，禁止写死 `[-1.0, 9.2]`；
2. 在上楼直走段、平台和下楼直走段分别测量宽度，不能让检查脚本混入转弯走廊；
3. 文件名采用 `eval_w{W}_r{h}_t{d}.pkl`，保存时把 `h/d/W` 写入 metadata；
4. 生成后从高度图与碰撞网格反向测量，误差超限则拒绝进入评测集；
5. 固定生成器版本、mesh 哈希、路径、起点、朝向、终止规则和 episode 长度。

核心固定矩阵：

```text
width: 1.2 / 1.8 / 2.8 m
riser: 0.10 / 0.12 / 0.15 / 0.18 m
tread: 固定 0.30 m
seed: 0 / 1 / 2
合计: 3 × 4 × 3 = 36 runs
```

另保留 `0.10/0.35/W=2.8` 作为 Stage 1 简单评测，不与核心矩阵混在一起。正式比较前，先用官方 epoch 41,250 权重在新矩阵上重建 baseline。

### 9.3 快速评测

每 500 epoch、单 seed：

1. 平地；
2. `h/d/W = 0.10/0.35/2.8 m` 上楼；
3. `h/d/W = 0.15/0.30/2.8 m` 上楼；
4. `h/d/W = 0.15/0.30/1.8 m` 下楼；
5. `h/d/W = 0.15/0.30/2.8 m` 上楼—平台—下楼。

记录：

```text
路径进度
到达级数
脚勾事件 / 摆动次数
膝碰撞事件 / 摆动次数
安全落脚 / 总落脚次数
楼梯前停留时间
楼梯速度 / 平地速度
AMP 分数
能耗
```

### 9.4 阶段评测

每个 Stage 结束时，上述场景运行 3 seeds。完整 `3 width × 4 riser × 3 seed` 矩阵只在最终候选 checkpoint 上运行。

### 9.5 最佳 checkpoint 选择

\[
\begin{aligned}
Score={}&
0.35S_{progress}
+0.20S_{landing}
+0.15S_{foot\_safe}\\
&+0.15S_{knee\_safe}
+0.10S_{velocity}
+0.05S_{AMP}
\end{aligned}
\]

硬约束：

- 平地表现下降不超过 5%；
- 不能以更高膝碰撞率换取进度；
- 不能在台阶前持续停顿；
- 不能通过穿模或放宽评测终止规则提升成绩。

最终在 checkpoint epoch 49250、49750、50250、50750、51250 中选择综合指标最佳者，不保证最后一个最好。

## 10. 训练分布最低要求

历史训练中 43/64 episode 一步都没上、上台阶事件只有约 1.57%。新课程必须满足：

- Stage 1–3 至少 70% episode 真正发生台阶接近事件；
- 至少 80% 楼梯 episode 的 `D_start` 位于该 Stage 目标范围；
- 斜面 tile 和斜面事件数必须为 0；
- 单独统计上楼、下楼、混合路线的事件数；
- 统计 riser/tread/width/start distance 的配置采样与实际事件直方图；
- 每个宽度档的实际楼梯接近事件数不得低于该档理论期望的 80%；
- 分宽度报告通过率、脚勾率、膝碰率、踩边率，禁止只给所有宽度的总体平均；
- 检查 `h/d/W` 联合分布，避免窄楼梯只与最简单 riser/tread 同时出现；
- 每阶段报告脚、膝、落脚三类事件数量，不能只报告 terrain tile 比例；
- 若台阶事件覆盖不足，优先修出生点和路线，不通过增加 epoch 补偿。

## 12. 执行顺序

```text
1. 实现直楼梯生成器，并让 h/d/W/steps/platform 全部真正生效
2. 实现“最近立板距离 + 行走方向 + 横向边界”的出生采样
3. 生成 100+ tile，反向测量几何和实际采样分布，完成 P0 验收
4. 修复评测生成器与检查脚本，重建并冻结 36-run 网格
5. 实现并单元验证 reward 原始分量
6. 离线回放验证符号、范围、门控和多阶跨越
7. 用统一终止规则在新评测网格上重建官方 checkpoint baseline
8. 128–256 env × 30–50 epoch 冒烟并验证保存/恢复
9. 从官方 epoch 41,250 checkpoint 开始 Stage 1
10. 每 500 epoch 跑快速评测并分宽度报告
11. 按门槛推进 Stage 2、3、4
12. 最终候选跑完整矩阵与视频
13. 选择最佳 checkpoint，不默认使用最后保存
```

## 13. 成功判据

最终模型至少满足：

1. 平地能力相对基线下降不超过 5%；
2. 标准 0.15/0.30 楼梯能稳定上楼和下楼；
3. 混合路线能完成平地—上楼—平台—下楼—平地；
4. 脚勾立板事件显著低于旧 checkpoint；
5. 膝/小腿碰撞不再被频繁触发；
6. 危险踩边率低于 5%；
7. 楼梯前速度不低于平地速度约 80%；
8. 不出现持续停顿、夸张高抬腿或跪行；
9. 一次跨多阶的安全动作不被错误惩罚；
10. `W=2.8 m` 标准楼梯稳定通过，`W=1.8 m` 不出现明显横向碰壁或踩空；
11. `W=1.2 m` 困难楼梯的失败能够归因于真实窄宽度，而不是评测网格裁切；
12. 所有结论来自固定协议、多 seed 评测，而不是训练 reward。

## 14. 一句话总结

> 先让直楼梯的 `h/d/W/D_start` 和评测网格真实可控，再使用固定的 `0.6 task + 0.4 AMP` 与一次性 warmup；10000 epoch 只通过可验证的踏高、踏深、有效宽度和路线课程增加难度，不用错误几何或反复改奖励掩盖覆盖不足。
