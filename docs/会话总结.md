# PACER 下楼实验 · 会话总结

> 时间：2026-11-01
> 目标：让 PACER 在自建楼梯上完成"从起点下楼"的动作，并给出可视化结果

---

## 一、目标与技术路线

### 最初设想

用 **TRACE（轨迹生成）+ PACER（地形适应控制）+ 自建楼梯**，让虚拟人从指定起点下楼，最终升级到多人高层疏散。

### 结论

| 模型 | 职责 | 是否需要 |
|---|---|---|
| **PACER** | 地形适应全身控制，输出 SMPL 24 关节 | ✅ 核心，必需 |
| **TRACE** | 2D 人群轨迹扩散（3 s 历史 → 5 s 未来） | ❌ 单人场景多余；多人时再加 |
| 自建楼梯 | 作为地形输入 | ✅ 必需 |

**理由**：TRACE 不知道高度、没有起点概念、视野只有 5 s；单人的下楼路径就是一条固定折线，直接喂给 PACER 即可。

### 关键认知

PACER 的**地形是观测而不是权重**——高度图（64×64、5 cm/格）以根为中心实时采样。因此**换楼梯不需要重训**，只需换地形数据。适用边界是训练分布内的几何（踢面 ≲0.2 m、踏步 ≳0.25 m）。

## 二、PACER 的机制（已通过反解验证）

### 2.1 轨迹 τ^s

```
TrajGenerator 生成 101 个顶点的折线（世界坐标）
  ↓ calc_pos：按时间线性推进顶点索引（等时不等距 → 必须等距重采样以保速度恒定）
  ↓ _fetch_traj_samples：以 0.5 s 间隔采样 10 个点（覆盖 4.5 s）
  ↓ compute_location_observations：转到角色局部坐标系，只取 XY
策略观测（20 维）
```

关键参数（`pacer.yaml`）：

| 参数 | 值 | 含义 |
|---|---|---|
| `episodeLength` | 300 步 @30 Hz | episode = **10 s** |
| `numTrajSamples` | 10 | 10 个路点 |
| `trajSampleTimestep` | 0.5 s | 路点间隔 |
| `num_verts` | 101（硬编码） | 折线顶点数 |
| `_dt` | 0.1 s | 每段时长 |

**隐含速度 = 路径总长 / 10 s**。这是本会话后期发现的关键约束：

| 路径长度 | 隐含速度 | 评价 |
|---|---|---|
| 7.88 m（20 级楼梯） | 0.79 m/s | ✅ 合理 |
| 2.40 m（5 级楼梯） | **0.24 m/s** | ❌ 太慢，策略会原地蹭 |
| 21.3 m（测试用） | 2.13 m/s | ⚠️ 偏快 |

### 2.2 观测变换（精确复现，误差 0.0°）

用 dump 的数据反解出策略实际看到的坐标变换：

```python
q_wxyz = root_states[3:7][[3,0,1,2]]        # Isaac Gym 存的是 (x,y,z,w)
q_adj  = q_wxyz ⊗ conj([0.5,0.5,0.5,0.5])   # 移除 SMPL base rotation
heading = atan2( R(q_adj)·x̂ 的 y, x )
local   = R(heading)⁻¹ · (waypoint − root)  # 取 xy
```

验证方法：在 1412 维观测里用"成对范数"（旋转不变）定位到路点块位于 `obs[368:388]`，再比对方向夹角：

| 假设 | 夹角 |
|---|---|
| `(w,x,y,z)` | 78–83° |
| `(w,x,y,z)` + 去 base | 161–167° |
| `(x,y,z,w)` | 176–179° |
| **`(x,y,z,w)` + 去 base** | **0.0°** ✅ |

**结论：PACER 的观测代码没有 bug，`has_upright_start: False` 才是正确设置。**

### 2.3 终止条件

```python
has_fallen  = 非脚部刚体接触力 > 50 N
tar_fail    = |轨迹点(当前时刻) − 根位置| > fail_dist (= 4 m)
has_failed  = has_fallen OR tar_fail
```

注意：`tar_fail` 用的是**当前时刻的轨迹点**，所以走慢了会被判失败。

## 五、关键实验与数据

### 5.1 地形生成与验证

**生成（20 级，riser 0.15 / tread 0.32 / 宽 1.2）**

```
vertices (324, 3)   faces (162, 3)
heightmap (192, 64) @ 20 px/m  →  9.6 m × 3.2 m
z range 0.00 .. 3.00    20 次跳变，每次 0.150
```

**高度图 ↔ 网格一致性**：13 个采样点全部一致（diff = 0.00）

**碰撞网格（小球跌落）**：24 个测点中 **20 个完全一致**（3.00 / 2.85 / 2.70 / 2.25 / … / 0.00）；4 个失败点都紧贴踢面（小球半径与竖直面角接触造成穿插），不是网格漏洞。

**结论：地形数据是正确的。**

### 5.2 PACER 行为（平地对照）

| 实验 | 位移 | 重置 | 结论 |
|---|---|---|---|
| 平地 + **程序化轨迹** | 4.6 m / 4 s | 0 | ✅ 策略本身正常 |
| 平地 + 固定路径 **−x**（默认朝向） | 3.45 m（1.9 m/s） | 0 | ✅ 路径注入正确 |
| 平地 + 固定路径 **+x**（yaw 0） | 0.13 m | 8 | ❌ |

### 5.3 楼梯实验

| 实验 | 结果 |
|---|---|
| 20 级 + 路径 +x | 7 重置，x 不动 |
| 镜像 20 级 + 路径 −x | 6 重置，x 不动 |
| 20 级 + `has_upright_start: False` | 23 重置（更差，已回滚） |
| 20 级 + 关闭摔倒判定 | **0 重置，x 0.40→2.95，但 y 漂到 18 m**（横向失控） |
| **5 级 + 路径 −x** | **走下一段**（x→−1.34，z 1.74→0.84），2 次重置 |

**重要**：关闭摔倒判定后角色会走（x 前进 2.5 m），只是横向漂出 1.2 m 宽的楼梯——说明"不会走"这个判断是错的。

### 5.4 初始朝向标定

修正四元数顺序后，`--start_yaw` 与视觉正面呈**线性关系**：

| 请求 | 视觉正面（脚趾−脚踝） |
|---|---|
| 0° | −20.7° |
| 92° | 69.7°（+90.4°） |
| 202.3° | −179.1° |

最终确定的是 **90°（`--start_yaw 1.5708`）**：这是**已验证正确**的初始位姿。

| 项 | 值 |
|---|---|
| 地形 | `stairs05_neg`（沿 **−x** 下降） |
| 出生点 | `(0.0, 0.0)` |
| 路径方向 | −x |
| **初始位姿** | **`--start_yaw 1.5708`（90°）** ✅ |

补充说明：90° 与 112.3° 的**数值结果几乎相同**（dx = −0.28、dz = −0.47、7 次重置），
但**画面上只有 90° 的朝向是对的**——说明"用数值反推朝向"不可靠，必须看渲染帧确认。

## 七、当前未解决的问题

### 7.1 主要卡点：路径隐含速度过慢

5 级楼梯的路径只有 **2.4 m / 10 s = 0.24 m/s**，10 个路点只铺开 **0.36 m**。策略被告知"目标就在脚前 4 cm"，得不到前进方向。

**修法（不需要改代码）**：路径总长保持 **8–10 m**，楼梯段短时在底部延伸地面直路。

```
5 级楼梯路径： (0,0,0.75) → (-2.4,0,0) → (-8.5,0,0)     # ≈8.5 m → 0.85 m/s
```

### 7.2 其他待查项

| 项 | 说明 |
|---|---|
| 横向漂移 | 关闭摔倒判定时 y 从 0 漂到 18 m（3.6 m/s），原因未定 |
| 5 级 vs 20 级差异 | 5 级能走一段、20 级完全不动，与路径速度/高度差都有关 |
| 落脚质量 | PACER 不保证踩准踏板（高度图 6.25 cm/格，脚长 25 cm） |

## 九、经验与注意事项

### 工具链

1. **Windows PowerShell 5.1 会把 UTF-8 无 BOM 脚本按 GBK 解码** —— 含中文路径的脚本必须写成 UTF-8 with BOM，或全用 ASCII。
2. **不要用嵌套引号的 `ssh host "复杂命令"`** —— 一律写成脚本文件再 `scp` + `bash`。
3. **`Set-Location` 不改变子进程的 cwd** —— `scp` 传相对路径会失败。
4. AutoDL 的 SSH 长命令容易断（几分钟），长任务一律 `nohup ... &` 后台跑 + 轮询日志。

### 科学方法

1. **先把"能不能跑"和"跑得对不对"分开**：平地对照实验是判断策略是否正常的关键基准。
2. **用可量化的指标替代"看起来对不对"**：如"脚趾−脚踝向量"测朝向、"成对范数"在观测里定位路点块。
3. **不要过早锁定单一根因**：本会话中"朝向""网格""观测变换"都曾被误判为主要原因。
4. **随机初态会让 A/B 对比失效**：`stateInit: Random → Start` 之后结果才可复现。

## 十、下一步建议

按优先级：

1. **修正路径长度**（8–10 m），重跑 5 级楼梯，看是否走通；
2. 若走通则逐级放大：5 → 10 → 15 → 20 级，找到失效分界；
3. 查横向漂移（关闭摔倒判定时的 18 m 偏移）；
4. 稳定后再考虑 TRACE（多人场景）与落脚规划（MDPI 那套）。
