# 多层建筑 · 分层高程图方案（设计计划）

> 目标：在**真实堆叠的三层建筑**（每层 XY 必重叠）里，让 PACER 从 3F 起点出发，
> 经两段 stage4 难度楼梯下降到 1F 指定点停下。地形按「地形大块」分层采样。

---

## 0. 一句话方案

**物理用一张完整 3D trimesh（楼层真实堆叠），感知用「每块一张高度图 + 落点判块」。**

块只有两种：`floor`（楼层平面）与 `stair`（楼梯）。相邻块在**表面完全相同**的
水平条带上重叠 1.5 m，因此切块时观测值不变 —— 转场无跳变，不需要状态机。

---

## 1. 为什么不能用一个 heightfield

单个 `heightsamples[ix, iy]` 在每个 (x,y) 只能存一个高度。三层楼板在平面上重叠，
必须存三个高度。

PACER 里**所有地形相关计算都收敛到同一个入口**：

```
get_heights()            ┐
get_center_heights()     ├─→ terrain.world_points_to_map() → heightsamples[px, py]
_sample_static_terrain() ┘        （地形观测 1024 维 / root 高度 / 脚底落地奖励）
```

所以只要把 `heightsamples[px,py]` 换成 `heightsamples[block, px, py]`，三处一起解决。

## 2. 已确认的事实（都是实测/源码，不是推测）

### 2.1 stage4 楼梯参数（`pacer_stage4_stairs.yaml` 原文）

```yaml
stair_riser_min: 0.08        stair_riser_max: 0.22
stair_tread_min: 0.26        stair_tread_max: 0.38
stair_width_bins: [3, 2.8, 2.4, 2, 1.8, 1.6, 1.2]
stair_width_probs: [0.05, 0.10, 0.20, 0.20, 0.20, 0.15, 0.10]
stair_up_steps_min: 8        stair_up_steps_max: 12
stair_platform_min: 1.5      stair_platform_max: 2.0
stair_approach_buf: 1.0      stair_runout: 2.0
stair_side_depth: 1.5        # 走廊外侧是坑，W 才是真实宽度
```

### 2.2 地形观测是「相对高程」，不是「绝对高程」 ⚠️ 关键

所有 stage 配置都是：

```yaml
use_center_height: true
rootHeightObs: False
```

对应代码（`humanoid_pedestrain_terrain.py` L1017-1018）：

```python
heights = center_heights - self.measured_heights        # center = 脚下中心采样均值
heights = torch.clip(heights, -3, 3.) * self.height_meas_scale   # scale = 5
```

**推论：一块完全平坦的地面上，1024 维地形观测全是 0。**

实测证据（1000 epochs 的 stage6 权重）：

| 场景 | 地形观测恒定维 | 结果 |
|---|---|---|
| 8×12 m 大平台 | **1012 / 1024**（只有 {0, 15}） | **冻结**：16.6 s 只走 1.6 m |
| 2.4 m 窄走廊 | **0 / 1024** | **正常**：2.0 m/s，4 次重置 |

**这是本项目最重要的一条设计约束：**

> **任何一块地形的宽度必须 < 4 m**（观测 patch 是 4×4 m，`sensor_extent=2`）。
> 否则站在中间时 patch 全空 → 策略失去地形信息 → 僵住。

→ **楼层平面设计成 3.4 m 宽的走廊**（不是大厅）。3.4 < 4.0，
横向永远看得见两侧边界，patch 不可能全空。

### 2.3 速度与踏面失配

实测控制器在平地上跑 **2.0 m/s**；stage4 踏面 0.26–0.38 m。
0.26 m 踏面 = **7.7 步/秒**，物理上不可能迈开 → 必然踩空。

→ 本方案**踏面取 stage4 上界 [0.32, 0.38]**；下界留给后续降速实验。

### 2.4 层高必须让角色走得过去

角色高约 1.7–1.85 m。楼板是真实几何，下层角色的头顶就是上层楼板：

```
层高 H < 2.2 m  →  走在 1F 会撞头（策略不知道天花板，不会低头）
```

stage4 的 `N × h` 范围是 `[0.64, 2.64]`。取 **H = 2.4 m 固定**，
则 `h = H / N`：

| N | h | 是否在 stage4 区间 [0.08, 0.22] |
|---|---|---|
| 11 | 0.218 | ✅ |
| 12 | 0.200 | ✅ |
| 10 | 0.240 | ❌ 超上界 |

→ **N ∈ {11, 12}，h = 2.4/N，其余参数按 stage4 分布采样。**

## 3. 数据结构

### 3.1 地形大块

```python
@dataclass
class Block:
    id: int
    kind: str            # "floor" | "stair"
    heightmap: np.ndarray   # (nx, ny) float32, 全局网格，米；无面处 = PIT(-1.5)
    walkable: np.ndarray    # (nx, ny) int8
    z_ref: float            # 该块的基准高度（floor 用；stair 用起止端）
```

全局共用一套 `(nx, ny)` 网格与一个世界坐标系 —— **不做局部坐标系**，
这样判块、A\*、路径都在同一空间里，不需要坐标变换。

### 3.2 重叠区规则

**只在「两块表面完全相同」的地方重叠**，宽度 1.5 m。

```
        floor(2F) 的 heightmap
        ├──────────────────┐
                           ├────────────┤   ← 重叠 1.5 m：两块高度完全相同（都是 2F 楼板）
                                        │
                 stair(A) 的 heightmap  ├─────────────┤
```

楼梯块的 heightmap 因此包含三段：

```
[ 1.5 m 上层楼板(平) ] [ N 级踏步 ] [ 1.5 m 下层楼板(平) ]
     ↑ 与上层 floor 重叠        ↑ 独占        ↑ 与下层 floor 重叠
```

**重叠区内两块值完全一致 → 切块不改变观测 → 无跳变。**
这是消除转场问题的根本手段，比滞回更彻底。

### 3.3 判块规则（落点 + 方向）

```python
def update_block_id():
    # 1) 落点：谁在这里有我脚下的支撑面（硬约束）
    cand = [m for m in range(NB)
            if abs(surface[m](xy) - foot_z) <= 0.15]

    # 2) 方向：只在重叠区有意义，按楼梯口法向决胜
    if len(cand) == 1:
        new = cand[0]
    elif len(cand) > 1:
        s = [dot(vel_xy, portal_normal[cur][m]) for m in cand]
        new = cand[argmax(s)] if max(s) >= 0.3 else cur
    else:
        new = cur                       # 悬空（跳跃/跌落中）→ 保持

    # 3) 连续 3 帧一致才提交
    ...
```

三条性质：
- **落点是硬约束**：跳到 1F 上，候选里只有 1F，方向再错也切不错
- **方向只在重叠区起作用**，而重叠区两块等高 → 判错 1–2 帧几乎零代价
- **悬空保持**：跌落过程中不切块

## 4. 场景设计

### 4.1 总体

- **3 层**：1F(z=0) / 2F(z=2.4) / 3F(z=4.8)
- **无墙体**：只有楼板与楼梯，从外部可直接看见内部（本轮要求）
- 每层楼板是 **U 形走廊**，宽 **C = 3.4 m**（满足 §2.2 的 <4 m 约束）
- 两段楼梯分别位于东西两条走廊，各连通上下两层

### 4.2 平面布局

```
y
↑
12  ┌───────────────────┐
    │      北侧连接段     │   x∈[0,10.8], y∈[8.6,12]
 8.6├─────────┬─────────┤
    │         │         │
    │  西走廊  │  东走廊  │   各宽 3.4 m
    │ x[0,3.4]│x[7.4,10.8]
    │         │         │
  0 └─────────┴─────────┘
    0       3.4 4.0    7.4      10.8   x
```

- **楼梯 A（3F→2F）**：位于西走廊，`x∈[0.2,3.2]`（W=3.0），沿 **+y** 下行
  洞口在 3F 楼板上，`y∈[3.0, 3.0+L_A]`
- **楼梯 B（2F→1F）**：位于东走廊，`x∈[7.6,10.4]`（W=2.8），沿 **-y** 下行
  洞口在 2F 楼板上，`y∈[8.0-L_B, 8.0]`

### 4.3 默认实例参数

| 项 | 值 |
|---|---|
| 走廊宽 C | 3.4 m |
| 层高 H | 2.4 m |
| 楼梯 A | W=3.0，N=12，h=0.200，d=0.34 → **L_A = 4.08 m** |
| 楼梯 B | W=2.8，N=11，h=0.218，d=0.36 → **L_B = 3.96 m** |
| A 洞口（3F） | x∈[0.2,3.2]，y∈[3.00, 7.08] |
| B 洞口（2F） | x∈[7.6,10.4]，y∈[4.04, 8.00] |
| 起点（3F） | (1.7, 1.2) —— 在 A 洞口以南的实心楼板上 |
| 终点（1F） | (9.0, 1.2) —— B 洞口以南，留 1.6 m 缓冲 |
| 重叠带 | 每段楼梯两端各 1.5 m（在上/下楼板上，与楼梯块等高） |

**路线（约 18 m）**

```
3F (1.7,1.2) ──+y──> A洞口南缘 (1.7,3.0)
            ──下 A(12级)──> 2F (1.7,7.08)
            ──+y──> 北侧连接段 ──东转──> 东走廊 (9.0,8.6)
            ──-y──> B洞口北缘 (9.0,8.0)
            ──下 B(11级)──> 1F (9.0,4.04)
            ──-y──> 终点 (9.0,1.2) 停下
```

### 4.4 生成器必须断言的几何约束

1. 每段楼梯的**底端落在下层实心楼板上**（不能落在洞里）
2. 两段楼梯 footprint **XY 不重叠**
3. 每层楼板上「除自身洞口外」全为实心
4. 上下层走廊边界对齐或包含（保证重叠带存在）
5. **任何一条能行走的路径上，离边缘的最大横向距离 < 2.0 m**（§2.2 约束）
6. 层高 ≥ 2.2 m（角色可通过）

## 5. 规划：分层 A\*

**不做 3D 搜索。** 楼层之间用一张小图（楼层图），每层用普通 2D A\*。

```python
block_seq = [3F, STAIR_A, 2F, STAIR_B, 1F]      # 3 层单楼梯 = 一条链

segs = []
for i, blk in enumerate(block_seq):
    beg = START if i == 0 else portal_in[i]
    end = GOAL  if i == len-1 else portal_out[i]
    segs.append(A_star(blocks[blk].heightmap, beg, end,
                       max_climb=0.28))          # > 最大单级 0.218
path = concatenate(segs)
```

- **portal 双投影**：同一个世界坐标，在上层块里当 A\* 的终点，在楼梯块里当起点
- `max_climb = 0.28` 必须大于 stage4 的最大单级 0.218，否则 A\* 拒绝上台阶；
  同时远小于层高 2.4，不会误判为可跨越
- 代价函数沿用现有实现：最大爬升约束 + 走廊居中 + 离坑距离

## 7. 分阶段实施

| 阶段 | 内容 | 验收标准 |
|---|---|---|
| **S1** | 生成 3 层场景 + 分层高度图 + 跑通判块（先不改 A\*，手工给块序列） | (a) 高度图与 mesh 在各块探针点吻合；(b) dump 里 `block_id` 序列为 3F→A→2F→B→1F；(c) 角色从 3F 走到 1F 不摔 |
| **S2** | 每层普通 2D A\* + portal 拼接 | A\* 路径与手工路径偏差 < 0.5 m |
| **S3** | 终点停下（stage6 的 `success_requires_stop`）+ 自动录像 + dump 分析 | 到达 1F 终点 1 m 内且末段速度 < 0.5 m/s |
| **S4** | （可选）踏面下界实验 / 随机化转场时机 | 稳定通过 5 个随机种子 |

**S1 是关键验证点**：如果分层高度图这套表示能让角色从 3F 走到 1F，
说明表示是对的，后面全是工程。

## 8. 风险与对策

| 风险 | 证据 | 对策 |
|---|---|---|
| **大平地 → 观测全零 → 策略僵住** | 实测 8×12 m 平台 1012/1024 恒定维，16.6 s 只走 1.6 m | 走廊宽 **3.4 m < 4 m**，横向永远看得见边界 |
| **楼梯口踩空** | 实测复现 4 次，每次都在楼梯口 | 踏面取上界 [0.32,0.38]；若仍踩空则降速（减小 `traj_dt`） |
| **转场观测跳变** | — | 重叠带 1.5 m，两块等高 |
| **判块抖动** | — | 3 帧防抖 + 悬空保持；且重叠区判错零代价 |
| **层高不足撞头** | 角色 1.7–1.85 m | 层高固定 2.4 m |
| **A\* 拒绝上台阶** | riser 最大 0.218 | `max_climb = 0.28` |
| **物理 mesh 三角面过多** | 训练地形曾因 44M 面 SIGSEGV | 全场控制在 < 1M 面；必要时 RES 降到 0.075 |

## 10. 验证方法

1. **几何一致性**：对每块，在 4–6 个探针点比较 `heightmap[px,py]` 与 mesh 顶点 z，
   要求误差 < 0.02 m（单块内）
2. **判块序列**：dump 里 `block_id` 应单调经过 `[3F, A, 2F, B, 1F]`，无来回跳
3. **轨迹**：z 应从 4.8 单调降到 0，中间在 2.4 处停留（2F）
4. **终点**：与目标距离 < 1 m，末段 2 s 平均速度 < 0.5 m/s
5. **对照**：同场景下用单层 heightfield（只有 1F）跑一遍，确认差异来自分层机制

## 11. 明确不做的事（本轮）

- 不做墙体（要求：从外部能看见内部）
- 不做天花板建模相关的高度图处理（层高 2.4 m 足够，物理上不接触）
- 不做体素表示（Gallant 路线），那需要换观测 + 重训
- 不做单跑多楼梯的多路径选择（楼层图是一条链）
