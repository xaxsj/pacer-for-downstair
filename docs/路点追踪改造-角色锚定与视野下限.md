# 路点追踪改造：角色锚定 + 视野下限

> 日期：2026-11-02
> 适用：`pacer-main`，`HumanoidPedestrianTerrain`（含 `HumanoidPedestrian`）
> 结论：路点采样从「全局时间轴」改为「角色锚定的局部目标」，并设视野下限 **1.0 m**。

---

## 一、问题

PACER 的观测里只有 10 个未来路点的**相对位置**（`compute_location_observations` 取 `[..., 0:2]`，只有 XY、无归一化）。原始实现按**时间**采样：

```python
# _fetch_traj_samples
timestep_beg = progress_buf * dt
```

带来两个毛病：

| 现象 | 机理 |
|---|---|
| **稳态超前** | 参考点按时间轴自己往前走（实测 0.26 m/s），角色步速 0.33 m/s → 每秒净超前 0.067 m，20 s 累计 +1.34 m（峰值 1.78 m） |
| **倒着走（backpedal）** | 路点落到身后时，策略转向去"面对"它；观测里"超前 1 m"和"超前 2 m"只差整体平移，没有显式信号可纠正 |

实测（时间锚定，20 级 / 5 m 宽 / `traj_dt 2.94`）：稳态超前 1.41 m，倒退帧 5%（含 −0.31 m/s 持续 18 帧），航向从 179° 转到 +28°。

---

## 二、改法：三处统一锚定

原始代码在三个地方都挂在全局时间轴上，必须一起改，否则训练时奖励与观测互相矛盾。

```python
# 新增 HumanoidTraj._anchored_time(env_ids, sample_offset=0)
#   角色 XY 投影到 101 顶点折线 -> 归一化相位 u
#   -> 等效时间 = u * traj_duration + (view_min / total_arc) * traj_duration
#                  + sample_offset * traj_sample_timestep
```

| 位置 | 改动 | `sample_offset` |
|---|---|---|
| `_fetch_traj_samples`（观测） | `timestep_beg = _anchored_time(env_ids)` | 0 |
| `_compute_reset`（tar_fail） | `tar_pos = calc_pos(env_ids, _anchored_time(env_ids, 0))` | 0 |
| `_compute_reward`（奖励） | `tar_pos = calc_pos(env_ids, _anchored_time(env_ids, 1))` | 1（瞄准下一个路点，避免奖励退化成常数） |

**没有重训**：观测语义仍是「10 个相对位置」，只是采样起点换了。

### 效果

| 指标 | 时间锚定 | 角色锚定 |
|---|---|---|
| 稳态超前 | 1.41 m（峰值 1.78） | **0.011 m**（峰值 0.049） |
| 倒退帧 | 5% | **0** |
| 横向漂移 | 0.305 m | **0.136 m** |
| 摔倒 | 0 | 0 |
| 走完 20 级 | 约 25 s | **约 6.7 s**（1.3 m/s，接近正常人下楼） |

## 三、视野下限（`PACER_VIEW_MIN`）

锚定后仍有一个问题：**当前方最近的可见路点太近时，策略会转向（背对前进方向走）**。

于是给整组路点加一个整体前移量（相邻间距**不变**）：

```
路点弧长位置 = view_min, view_min + s, view_min + 2s, ... , view_min + 9s
```

它约束的是「**第一个路点离身体多远**」，不是「点与点之间隔多远」。

### 二维扫描选值（`script/sweep_2d.py`，20 级 / 5 m 宽，各 300 帧）

| `traj_dt` | 间距 | `view_min` | 平均速度 | 峰值速度 | **航向误差** | 横向漂移 | 摔倒 |
|---|---|---|---|---|---|---|---|
| 1.0 | 0.26 | 0 | 0.572 | 1.62 | **138.2°**（掉头） | 0.181 | 0 |
| 1.0 | 0.26 | **1** | 0.782 | 2.17 | **7.5°** | 0.074 | 0 |
| 1.0 | 0.26 | 2 | 0.783 | 2.88 | 17.6° | 0.079 | 0 |
| 2.0 | 0.52 | 0 | 0.778 | 1.67 | 14.4° | 0.141 | 0 |
| **2.0** | **0.52** | **1** | 0.781 | 2.56 | **5.0°** ⭐ | **0.076** | 0 |
| 2.0 | 0.52 | 2 | 0.782 | 3.28 | 19.7° | 0.125 | 0 |
| 3.0 | 0.78 | 0 | 0.780 | 1.91 | 13.7° | 0.070 | 0 |
| 3.0 | 0.78 | **1** | 0.784 | 2.93 | 8.1° | 0.093 | 0 |
| 3.0 | 0.78 | 2 | 0.782 | 3.96 | 20.2° | 0.137 | 0 |

三条规律：

1. **`view_min = 0` 在任意间距下都差**（13.7°~138.2°），正是"倒着走"的成因
2. **`view_min = 1.0` 在任意间距下都好**（5.0°~8.1°），与 `traj_dt` 几乎无关 → 最稳健
3. **`view_min = 2.0` 反而变差**：2 m 盲区把策略逼成冲刺（峰值 2.9~4.0 m/s），速度一高航向就劣化

> 注意：`run_stairs.sh` 打印的 `waypoint spacing` 用的是 `L/10`，**不是真实参考速度**。
> 真实间距请用 `script/check_traj_speed.py` / `sweep_2d.py` 从 dump 反解。
> 实测映射：`traj_dt 1.0 / 2.0 / 3.0` → 间距 `0.26 / 0.52 / 0.78 m`。

## 四、最终配置

| 参数 | 值 | 位置 |
|---|---|---|
| `has_upright_start` | `True` | `pacer/data/cfg/pacer.yaml` |
| `stateInit` | `"Start"` | 同上 |
| **`PACER_VIEW_MIN`** | **1.0 m**（默认） | `pacer/env/tasks/humanoid_traj.py` |
| `PACER_TRAJ_ANCHOR` | `char`（默认） | 同上 |
| 推荐 `traj_dt` | 2.0（间距 0.52 m） | 命令行 `--traj_dt` |

推荐组合实测：航向误差 5.0°、末帧 2.5°、速度 0.781 m/s、横向漂移 0.076 m、0 摔倒、20 级走完。

### 开关

```bash
PACER_TRAJ_ANCHOR=time   # 回到原始的全局时间轴采样
PACER_VIEW_MIN=0         # 关闭视野下限
PACER_VIEW_MIN=2.0       # 更大的盲区（不推荐，会冲刺）
```

补丁脚本：`python script/patch_anchor_unify.py --apply | --revert | --status`

## 六、工程教训

1. **改源码必须同时改本地仓库和服务器**，否则仓库与现实脱节（本轮已两次踩坑，现已用 md5 对齐）
2. **补丁脚本必须保留原文件的行尾**，否则 CRLF/LF 差异会制造整文件 diff（`patch_anchor_unify.py` 已修）
3. **不要用 PowerShell 正则改含中文的源码文件**，编码会被破坏；用编辑工具或 Python 读写
4. **视频/截图不入库**（`.gitignore` 已加规则），states.pkl 可由 `*.pkl` 规则排除
